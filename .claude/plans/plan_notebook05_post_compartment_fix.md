So the notebook opens post-fix data. What it then *does* with that data was written against the
pre-fix compartments, and four things are now wrong — one of them a silent correctness bug.

### 1. The pooled `nerve_neuron` group silently loses its annotation (correctness bug)

`_load_tables` derives the join key with
`out["nerve_cluster"].str.replace("nerve_c", "", regex=False)` (lines 180–182). The nerve
compartment is no longer per-Leiden-cluster only: neurons are carried as one pooled LIANA group,
`nerve_neuron`, which contains no `nerve_c` substring and so passes through unchanged. It matches
no row in `nerve_cluster_annotations.csv`.

Measured on the live table: **2,679 of 48,581 nerve-side rows** fail the join. They get
`nerve_cell_type = ""`, are dropped from the Panel D interface matrix entirely, and fall back to a
bare `nerve_neuron` string in Panel C.

This is the exact failure the pipeline already guards against. `workflow/scripts/fair_utils.py:166`
defines `nerve_group_key()` for it, and `workflow/scripts/annotate_cluster_qc.py:147-150` carries
the comment *"A bare `removeprefix("nerve_c")` leaves `nerve_neuron` intact, which then matches no
purity row"*. The notebook is the one consumer that never adopted the helper.

The bug matters more than its row count: the neuron group is precisely the donor-dominated
population flagged in §2.2 of the review document (`dominant_sample_fraction = 0.4/0.5032`,
7–10 contributing samples). It should be visible and caveated, not invisible.

### 2. Panel A's compartment mapping is hardcoded and now wrong in both directions

`_compartment_census` hardcodes `_nerve_feeders = {neuron, excitatory_neuron, inhibitory_neuron,
astrocyte, oligodendrocyte, ependymal, opc}` and `ct == "microglia"` → immune. Both moved:

- `nerve_cells.cell_types` is now **only** `excitatory_neuron / inhibitory_neuron /
  oligodendrocyte` — astrocyte, opc, generic neuron and ependymal were deliberately excluded
  (`config/config.yaml`, §2.4 of the review).
- `immune_cells.source_labels` is now a **list of eight** (`microglia, macrophage, t_cell, nk_cell,
  b_plasma, neutrophil, dc, mast`), replacing the single `"microglia"` string — this is the
  ~2× immune-compartment growth described in §2.3.

Computed against the live `annotation_summary.csv`:

|  | notebook reports | truth per config |
|---|---|---|
| nerve | 194,080 | 36,712 |
| immune | 125,671 | 343,280 |
| "never enters any result" | 295,200 (48.0%) | 234,959 |

The callout also names `macrophage`, `t_cell`, `neutrophil`, `nk_cell`, `dc`, `b_plasma`, `mast`
as excluded from the analysis when all seven are now *in* the immune compartment.

### 3. Three narrative claims are now false

- *"This cohort's annotation resolves only 5 cell types … no `endothelial`, `opc`, `ependymal` or
  `tumor_gbm` category exists here at all"* — `annotation_summary.csv` now has **18** labels
  including `opc` (22,532), `ependymal` (34,597), `tumor_gbm` (10,270), `mural` (5,604).
- *"`mean_confidence` 5.96–15.29 here vs 0.11–0.73 in the reference"* — the live range is
  **0.95–28.11**.
- *"a **separate, unfixed defect** … see `markdowns/blocker_census_annotation_scoring.md`"* — that
  blocker **is fixed**. It is defect D1, and `workflow/scripts/scrna_annotate.py:102-135` now
  normalizes to log1p before `score_genes` and reverts afterward. The markdown itself still reads
  `Status: OPEN`, so it is stale too.
- Footer limit 4, *"11 of 35 nerve clusters fail batch QC"* — now **9 of 26** purity rows fail.

### 4. Panel F frames the v1.3.0 concordance as an agreement result

Its callout says *"Both rose once the scales matched."* Against the pre-normalization numbers that
happens to still be arithmetically true, but §2.5 is explicit that both moved **down** from the
post-normalization pre-compartment-fix values, that the reference's own nerve compartment was built
by the very logic this work removed, and that these numbers **must not be reported as a replication
result**. The panel currently invites exactly that reading.

## Approach

Scope confirmed with the researcher: **correctness + stale prose**, **remove Panel E entirely**,
**§2.5 option (a)** for the concordance panel. No new Snakemake rules, no new artifacts, no
shortlist re-derivation. Single file touched: `notebooks/05_census_nerve_immune_explorer.py`.

### A. Adopt the canonical group-key helper

In `_imports` (or a new small cell), put `workflow/scripts` on `sys.path` relative to
`project_root` and import the existing helpers rather than reimplementing them:

```python
sys.path.insert(0, str(Path(__file__).parent.parent / "workflow" / "scripts"))
from fair_utils import nerve_group_key, nerve_group_sort_key
```

`fair_utils` imports only stdlib + numpy + pandas (verified), so this is safe in a marimo kernel.
`E402` is already in the project's `extend-ignore` for exactly this pattern.

Then in `_prepare` (line ~180) replace the `str.replace("nerve_c", ...)` with
`out["nerve_cluster"].map(nerve_group_key)`.

### B. Give the pooled neuron group a label

`nerve_cluster_annotations.csv` covers Leiden clusters `0–24` only; `nerve_cluster_annotations.py`
never emits a row for the pooled group, so a correct join still leaves `neuron` unlabelled. Rather
than change the pipeline (out of scope), synthesize the row in `_load_tables` after reading
`nerve_ann_df`:

- `cluster_key = "neuron"`, `nerve_cell_type = "neuron"`, `nerve_score_type = "neuron"`,
  `nerve_type_agrees = True`, `label = "neuron | pooled excitatory + inhibitory"`,
  `interpretation` naming it as a pooled group carried outside the Leiden clustering.

Add a short comment recording *why* (the group is pooled by design — see
`config/config.yaml: nerve_cells.neuron_labels` and `fair_utils.nerve_group_key`'s docstring) so a
future reader does not "fix" it back.

Add a cheap assertion in `_load_tables` mirroring the pipeline's guard: if any row has a non-empty
`nerve_cluster` but no joined label, raise rather than silently render an empty cell type. This is
the notebook-side equivalent of the `[FAIR-ALERT]` in `annotate_cluster_qc.py:100-105`.

### C. Derive Panel A's compartments from config, not from a literal

`_load_config` currently keeps `config` local — add it to the cell's return so `_compartment_census`
can read it. Then:

```python
_nerve_labels = set(config["nerve_cells"]["cell_types"])
_immune_cfg = config["immune_cells"]
_immune_labels = set(_immune_cfg.get("source_labels") or [_immune_cfg["source_label"]])
```

(the `source_label` fallback mirrors the backward-compat note at `config/config.yaml:432`).

Third category: the tumor compartment is **CNV-derived and cuts across every predicted label**, so
it cannot appear in a census keyed on `cell_type_predicted`. Say that in the panel rather than
implying the remainder is unmodelled — the current "never enters any interaction result" phrasing
is what makes the number misleading.

Rewrite the callout to be computed rather than asserted, and replace the two false paragraphs with:
the §2.4 masking decision (astrocyte / opc / generic neuron / ependymal excluded **by decision, not
by biology** — with the measured purity table), and the §2.3 note that the immune compartment is now
eight labels rather than one, so **any pre-2026-08-05 "immune" finding was a myeloid finding**.

### D. Panel B — ordering and the donor-dominance caveat

`nerve_cluster_sample_purity.csv` now carries a non-numeric `neuron` row, so
`df.sort_values("cluster")` sorts lexically (`0, 1, 10, …, 9, neuron`). Use the helper that already
exists for this: `d.sort_values("cluster", key=lambda s: s.map(nerve_group_sort_key))`.

Add the §2.2 caveat to the panel's callout — the neuron group sits at 0.4 dominant fraction over
10 samples on this arm and 0.5032 over 7 on the full arm, so neuron-side axes are substantially one
patient's biology. `_n_fail` is already computed dynamically and needs no change.

### E. Remove Panel E

Delete `_replication_header` and `_replication_table` outright, plus:

- the `"reference_lead_targets"` entry in `_load_config`'s `paths` dict (this also removes it from
  the `mo.stop` missing-artifact check and from the export provenance hashes, both automatically),
- `lead_targets_df` from `_load_tables`'s reads and return tuple,

In its place, a short markdown cell explaining the removal: the shortlist predates the fix, was

### F. Panel F — keep the panel, drop the replication framing (§2.5 option a)

Keep the scatter and the numbers as a *diagnostic*, and rewrite the callout to state:

Delete the "both rose once the scales matched" sentence.

### G. Header, docstring, integrity banner, footer

- Module docstring and `_header`: keep the 2026-07-26 normalization history (still true and still
